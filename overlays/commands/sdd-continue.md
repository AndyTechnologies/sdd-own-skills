   SUPPORT-CONDITIONAL: the support phases (research, hard-verify, pre-experience, changelog) are OPT-IN/automatic organic phases; the architecture-lint is an ALWAYS-fired POST-apply hook. The ORCHESTRATOR routes them by inspecting artifact/change state in this step. They are NOT part of the `nextRecommended` token set and NEVER alter it — they join the pipeline at a hook point and are detected by artifact presence/state, not by a status token.
   - `sdd-research` → runs in PARALLEL with `explore` after both RFC gates (both consume the two RFC artifacts); the architecture-plan MAY launch an extra pattern-research lane. Trigger: post-RFC, pre-proposal evidence gathering requiring external/auditable sources — never serial-blocking explore.
   - `sdd-architecture-plan` → runs AFTER `spec` and BEFORE `design`, behind a USER gate: consumes `arch-rfc.md` + explore/research + the spec deltas (fail-closed on any missing input; never invents evidence) and produces the binding acta `arch-plan.md` with titled decisions. The USER approves the plan before design starts (interactive: explicit approval; auto: recorded, no interruption). A rejection returns to the Architecture Plan with the findings (max 2 rounds); a 3rd rejection stops with a report.
   - `sdd-architecture-lint` → runs ALWAYS POST-apply (after `apply`, before `verify`) — never pre-apply, no opt-out, no boundary-conditional skip. It is the second, independent eye on the implementation: axis 1 (requirements/scope) ALWAYS; axis 2 verifies the `arch-plan.md` acta decisions title-by-title against the design AND the implementation, FAILING CLOSED if the acta is missing. `N/A` applies ONLY to an empty/trivial change. A finding returns to `design` for correction (max 2 rounds); the lint carries no review/delivery/release authority.
   - `sdd-hard-verify` → OPT-IN gate after `verify` passes: NO (default) → proceed to close; YES → adversarial break testing on sensitive surfaces; a suite that PASSES despite an injected break is a testing error and control returns to Tasks with a gaps acta (max 2 rounds).

Trigger: the hard gate passed AND the change has not yet emitted a `changelog`. If the change has no consumer-facing behavior (per spec), the sub-agent returns the organic no-release opt-out and persistence is skipped.
   - `sdd-pre-experience` → runs between changelog and archive: persists the session failures per the artifact-store mode and proposes skill candidates to the user (never auto-creating them); fail-open — never blocks archive.
