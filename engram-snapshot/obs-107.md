# obs-107 [architecture] sdd-continue reconoce sdd-quest condicional (salta si confirmado)

**What**: Actualicé el comando `sdd-continue` para que reconozca la fase `sdd-quest` condicionalmente: solo la ejecuta si es necesario, saltándola si ya hay un quest confirmado de una corrida previa.
**Why**: El usuario pidió que `sdd-continue` no repita la quest si ya no quedan dudas nuevas que resolver (evitar re-entrevistas redundantes).
**Where**: /home/andy/.config/opencode/commands/sdd-continue.md (bloque "QUEST CONDITIONAL"), /home/andy/.config/opencode/opencode.json (sección "SDD Quest Phase" del orquestador), y las skills sdd-quest (persistencia con header `## Confirmation: confirmed|partial`).
**Learned**:
1. La lógica condicional: SI `nextRecommended=propose` Y no existe proposal → revisar artifact quest. Si `## Confirmation: confirmed` → SKIP quest (ir directo a propose). Si `## Confirmation: partial` → re-ejecutar quest. Si no existe quest → ejecutar quest. El quest nunca corre 2+ veces cuando ya está `confirmed`.
2. **Detección por header unificado**: el quest PERSISTE el artifact con header `## Confirmation: confirmed | partial` (con mayúscula, `##`, legible), y `sdd-continue` DETECTA ese header con el MISMO casing. No usar campo lowercase `confirmation:` — desalineado. Detección y persistencia deben matchear exactamente.
3. Distinción clave: en `/sdd-new` el quest SIEMPRE corre (primera alineación, explore→quest→propose). En `/sdd-continue` el quest es CONDICIONAL (solo cuando nextRecommended=propose y no hay quest confirmed).
4. En openspec se lee `openspec/changes/{change}/quest.md`; en engram se lee `sdd/{change}/quest` vía mem_get_observation (contenido completo markdown con el header). El header `## Confirmation:` está presente en ambos.
5. El quest NO es token del dispatcher nativo gentle-ai (sigue siendo paso del orquestador); en continue se decide por inspección del artifact quest, no por nextRecommended.
